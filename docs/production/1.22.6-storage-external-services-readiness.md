## 1. Executive Summary

This document establishes the production readiness standards, security boundaries, and operational guardrails for all file storage and external third-party service subsystems in the **Aforden** platform. As audited in Phase 1.22.1 and structured across subsequent phases, production readiness requires eliminating silent network hangs, preventing cross-tenant file collisions and path traversal, enforcing strict MIME validation against stored XSS, securing inbound webhook receivers, and establishing deterministic runtime environment resolution for external SaaS APIs.

### Key Accomplishments in Phase 1.22.6:
1. **Cloud Storage (AWS S3) Security Guardrails**:
   - Implemented upload payload size validation capped at **25 MB** (`MAX_UPLOAD_BYTES = 25 * 1024 * 1024`).
   - Implemented strict MIME type allowlisting/denylisting, rejecting dangerous executable and script types (`text/html`, `application/xhtml+xml`, `application/x-msdownload`, `application/x-executable`, `application/javascript`, `text/javascript`) with HTTP 400 `PAYLOAD_VALIDATION_FAILED` to eliminate stored Cross-Site Scripting (XSS).
   - Enforced path traversal prevention blocking `..` and `\` in object keys.
   - Enforced workspace tenant isolation: keys matching `workspaces/{workspaceId}/*` or `tenants/{workspaceId}/*` verify that the path belongs to the caller's active workspace, returning HTTP 403 `AUTHENTICATION_FAILED` on cross-tenant access attempts.
   - Restricted target buckets: calls cannot override the configured production environment bucket (`payload.bucket` mismatch returns HTTP 400).
   - Bounded presigned download/upload URL expiry between 1 second and 7 days (`MAX_EXPIRY_SECONDS = 604800`, AWS SigV4 maximum), defaulting safely to 1 hour (3600s).
2. **Next.js Image Optimization Whitelist (`next.config.ts`)**:
   - Hardened `images.remotePatterns` to allow only trusted image sources: Supabase Storage (`*.supabase.co`) and Amazon S3 (`*.s3.amazonaws.com`, `*.s3.*.amazonaws.com`, `s3.*.amazonaws.com`).
3. **Inbound Webhook Receiver Hardening**:
   - Verified that all inbound webhook endpoints (`/api/billing/webhooks/*`, `/api/integrations/webhooks/*`) require cryptographic signature verification before ingestion.
   - Confirmed webhook receivers are subjected to per-IP rate limiting via `applyApiSecurityMiddleware(request)` falling through to the unauthenticated IP rate limit bucket (`rl:rest:ip:${hash(clientIp)}` capped at 60 req/min), preventing DoS and replay flood attacks without exemptions.
4. **Outbound External API Resilience & Fault Tolerance**:
   - Attached deterministic network abort signals (`AbortSignal.timeout(10000)`) to outbound HTTP clients (`BrevoEmailProvider`, `BrevoEmailProviderAdapter`), eliminating unhandled socket hangs.
   - Hardened error logging across email providers to log sanitized status codes and messages while redacting request payloads and API keys.
   - Verified exponential backoff with full jitter in `retryOrchestrator` (`computeBackoffDelayMs`) for outbound integration calls.
   - Confirmed recursive credential redaction (`redactSensitiveData`) in integration audit logs, redacting `apiKey`, `secret`, `token`, `password`, `authorization`, and private key material.
5. **CORS & Origin Configuration**:
   - Confirmed public API CORS policy rejects wildcard origins (`*`) when `Access-Control-Allow-Credentials: true` is set.
   - Ensured inbound webhooks bypass browser CORS constraints to accept machine-to-machine HTTP POST requests from third-party webhook dispatchers.
6. **Multi-Environment Service Credential Separation**:
   - QuickBooks Online adapter dynamically selects between Intuit Sandbox (`https://sandbox-quickbooks.api.intuit.com`) and Production (`https://quickbooks.api.intuit.com`) based on tenant connection config or `QUICKBOOKS_ENVIRONMENT`.
   - Paddle Billing adapter dynamically routes between Sandbox (`Environment.sandbox`) and Production (`Environment.production`) based on `PADDLE_ENVIRONMENT`.
7. **Verification**:
   - 100% pass rate across the dedicated test suite: `tests/storage/storage-and-external-services.test.ts` (18 tests passing).

## 2. Cloud Storage Architecture (AWS S3)

### 2.1 File Storage Boundaries
File storage is abstracted through [`lib/integrations/adapters/awsS3Adapter.ts`](file:///d:/Download/aforden/lib/integrations/adapters/awsS3Adapter.ts). All operations execute via AWS SigV4 authenticated requests or presigned URLs.

| Constraint | Limit / Setting | Rationale / Defense |
| :--- | :--- | :--- |
| **Max File Upload Size** | 25 MB (`26,214,400` bytes) | Prevents memory exhaustion and excessive S3 bandwidth consumption |
| **Default URL Expiry** | 3,600 seconds (1 hour) | Limits temporal exposure of presigned links |
| **Max URL Expiry** | 604,800 seconds (7 days) | Strictly enforced upper bound matching AWS SigV4 specification |
| **Restricted Bucket** | Configured connection bucket | Disallows caller from writing to or reading from arbitrary AWS buckets |
| **Disallowed MIME Types** | HTML, XHTML, EXE, JS, Script | Eliminates stored XSS and malware distribution risks |
| **Path Traversal Guard** | Rejects `..` and `\` | Prevents directory escaping in object keys |
| **Tenant Key Isolation** | Must match caller `workspaceId` | Prevents cross-workspace data access |

### 2.2 Next.js Remote Image Whitelisting
To prevent SSRF and unrestricted image proxying through `/_next/image`, [`next.config.ts`](file:///d:/Download/aforden/next.config.ts) specifies:
```typescript
images: {
  remotePatterns: [
    { protocol: "https", hostname: "*.supabase.co", pathname: "/**" },
    { protocol: "https", hostname: "*.s3.amazonaws.com", pathname: "/**" },
    { protocol: "https", hostname: "*.s3.*.amazonaws.com", pathname: "/**" },
    { protocol: "https", hostname: "s3.*.amazonaws.com", pathname: "/**" },
  ],
}
```

### 2.3 File-Serving Route Authorization & Absence Audit
An exhaustive audit of all 136 HTTP route handlers across `app/api/**` was conducted to identify any endpoints that serve, stream, or return access to previously uploaded files:
1. **Zero File-Serving Endpoints**: No route in `app/api/**` currently streams stored files, proxies S3 downloads, or exposes presigned URL generation endpoints to clients.
2. **Dynamic In-Memory Report Streaming**: The only route streaming file content is `/api/reports/[...reportSlug]`, which generates CSV data on the fly in memory from database queries (`createReportCsvStream`). This route strictly verifies tenant membership via `await requireWorkspaceAuthorization(workspaceId)` before generating and streaming data.
3. **Architectural Rationale & Security Boundary**:
   - Files are never proxied through the Next.js serverless compute runtime, preventing serverless execution timeouts, memory exhaustion, and egress bandwidth amplification.
   - Presigned URLs are generated directly on the server by authorized internal services with the verified `workspaceId` baked into the object key path (`workspaces/{workspaceId}/*`).
   - S3 buckets enforce default private access (`BlockPublicAcls`, `BlockPublicPolicy`, `IgnorePublicAcls`, `RestrictPublicBuckets`). Third parties cannot guess paths or access files without valid, time-limited AWS SigV4 signatures.
   - The adapter's internal tenant isolation check ([`awsS3Adapter.ts:337-346`](file:///d:/Download/aforden/lib/integrations/adapters/awsS3Adapter.ts#L337-L346)) acts as defense-in-depth, rejecting any caller attempting to request a key outside its active workspace with HTTP 403 `AUTHENTICATION_FAILED`.

## 3. Inbound Webhooks & Rate Limiting

### 3.1 Receiver Security Surface
1. **Billing Webhooks** (`/api/billing/webhooks/[provider]`):
   - Cryptographically verifies incoming signatures (`Paddle-Signature` / `Stripe-Signature`).
   - Applies global API security rate limits via `applyApiSecurityMiddleware` (60 requests/minute per client IP under `rl:rest:ip:`).
2. **Integration Webhooks** (`/api/integrations/webhooks/[slug]`):
   - Dispatches through the 8-stage pipeline: signature verification, deduplication via idempotency key, tenant routing, capability payload validation, persistence, and audit logging.

### 3.2 Webhook CORS Exemption
Webhook endpoints are server-to-server endpoints invoked by third-party webhook dispatchers (Stripe, Paddle, Resend, Brevo, QuickBooks). They do not require CORS preflight headers and must not reject POST requests lacking browser `Origin` headers.

## 4. Outbound Integrations & Fault Tolerance

### 4.1 Network Timeouts
All outbound HTTP operations to third-party APIs (Brevo, Resend, Twilio, QuickBooks, Google) must declare explicit timeouts:
- **Email Providers** (`BrevoEmailProvider`, `BrevoEmailProviderAdapter`):
  `signal: AbortSignal.timeout(10000)` (10 seconds timeout).
- **Network Failures**: Caught and translated into structured `BrevoDeliveryError` or `IntegrationExecutionResult` with `isRetryable` classification.

### 4.2 Retry Backoff & Jitter
The integration engine in [`lib/integrations/execution/retryOrchestrator.ts`](file:///d:/Download/aforden/lib/integrations/execution/retryOrchestrator.ts) applies full jitter exponential backoff:
$$\text{Delay} = \min(\text{maxDelayMs}, \text{baseDelayMs} \times 2^{\text{attempt}}) \times \text{random}(0.8, 1.2)$$

### 4.3 Redaction of Sensitive Material
Before integration execution logs or errors are persisted to `IntegrationExecutionLog` or platform audit records, [`lib/integrations/execution/redaction.ts`](file:///d:/Download/aforden/lib/integrations/execution/redaction.ts) scrubs all sensitive keys (`apiKey`, `secret`, `token`, `password`, `authorization`, `privateKey`, `credential`).
