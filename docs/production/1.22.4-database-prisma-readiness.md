## 2. Supabase/PostgreSQL Production Connection Architecture

### 2.1 Pooled Runtime vs. Direct Migration Split

Prisma and PostgreSQL access is bifurcated to honor serverless pooling while permitting transactional DDL migrations:

```
                                +-----------------------------------+
                                |         Aforden Platform          |
                                +-----------------------------------+
                                         /                 \
                                        /                   \
                   [Runtime HTTP Requests]                 [DDL Migrations]
                                      /                       \
                                     v                         v
                       +---------------------------+   +-------------------------------+
                       | DATABASE_URL              |   | DIRECT_URL                    |
                       | Port 6543 (PgBouncer)     |   | Port 5432 (PostgreSQL Engine) |
                       | Transaction / Session Mode|   | Direct Session Connection     |
                       | ?pgbouncer=true           |   | Used by prisma.config.ts      |
                       +---------------------------+   +-------------------------------+
                                     \                         /
                                      v                       v
                                +-----------------------------------+
                                |   Supabase / RDS PostgreSQL DB    |
                                +-----------------------------------+
```

1. **Runtime Application Queries (`DATABASE_URL`)**:
   - Resolved by [`lib/prisma.ts`](file:///d:/Download/aforden/lib/prisma.ts) via `@prisma/adapter-pg`.
   - Connects to Supabase PgBouncer pooler on port `6543` with `?pgbouncer=true`.
   - Reuses connections across serverless lambda invocations.
2. **Schema Migrations & Prisma CLI (`DIRECT_URL`)**:
   - Resolved by [`prisma.config.ts`](file:///d:/Download/aforden/prisma.config.ts):
     ```ts
     datasource: {
       url: process.env["DIRECT_URL"] ? env("DIRECT_URL") : env("DATABASE_URL"),
     }
     ```
   - Connects directly to PostgreSQL server on port `5432`.
   - Required because transaction poolers (PgBouncer) reject session-level DDL locks, advisory locks, and migration state transactions.

### 2.2 Serverless Connection Pool Tuning ([`lib/prisma.ts`](file:///d:/Download/aforden/lib/prisma.ts))

In a serverless environment (Vercel), each container instance spins up its own in-process connection pool. Uncapped pools (e.g. node-postgres default of 10) exhaust Supabase pooler caps (`pool_size: 15` in standard session tiers) under moderate traffic bursts.

Aforden implements [`resolvePrismaPoolConfig()`](file:///d:/Download/aforden/lib/prisma.ts) with serverless-safe defaults:

| Setting | Default (Production) | Default (Development) | Override Mechanism | Operational Rationale |
| :--- | :---: | :---: | :--- | :--- |
| `max` (Connection Limit) | **5** | **10** | `PG_POOL_MAX` env or `?connection_limit=N` | Prevents pool exhaustion across horizontally scaled lambda instances |
| `connectionTimeoutMillis` | **5,000 ms** | **5,000 ms** | `PG_POOL_TIMEOUT_MS` or `?pool_timeout=N` | Fails fast (5s) rather than holding caller requests in prolonged queue |
| `idleTimeoutMillis` | **10,000 ms** | **10,000 ms** | `PG_IDLE_TIMEOUT_MS` env | Reclaims idle connections rapidly when lambda instances freeze |

### 2.3 SSL Enforcement Requirements
All production connection strings must enforce TLS in transit. The production URI must satisfy:
- Scheme: `postgresql://` or `postgres://`
- Protocol parameters: `?sslmode=require` or `?sslmode=verify-full`
- Pooler parameters: `&pgbouncer=true` (for port 6543)
- Canonical production format:
  ```text
  postgresql://postgres.[PROJECT_REF]:[PASSWORD]@[HOST]:6543/postgres?pgbouncer=true&sslmode=require
  ```

Added to [`package.json`](file:///d:/Download/aforden/package.json):
```json

  "postinstall": "prisma generate"
}
```
**Execution Guarantee**: Whenever `npm install` executes—whether locally, on a CI runner, or during Vercel's automated build step—`prisma generate` runs automatically immediately after dependencies are linked, ensuring compiled TypeScript types are always up to date prior to `next build`.

## 4. Production Migration Strategy & Rehearsal

### 4.1 Migration Command Standard
* **Production Command**: `npx prisma migrate deploy`
  - Applies all unapplied migrations from `prisma/migrations/` in strict chronological order.
  - Never prompts for user input.
  - Never resets the database or drops existing columns unexpectedly.
* **Prohibited in Production**:
  - `prisma migrate dev` (prohibited: resets databases if drift is detected).
  - `prisma db push` (prohibited: bypasses migration history tracking).

### 4.2 Manual Gated Pre-Deployment Process (Operational Gap Documented)
Because no automated CI/CD pipeline currently exists in the repository (confirmed in Phase 1.22.3), production migrations must be executed as a **manual gated pre-deploy step**:

```bash
# Step 1: Export production direct connection string (never commit)
export DIRECT_URL="postgresql://postgres.[PROJECT_REF]:[PASSWORD]@[HOST]:5432/postgres?sslmode=require"

# Step 2: Verify migration status
npx prisma migrate status

# Step 3: Deploy pending migrations
npx prisma migrate deploy

# Step 4: Verify health endpoint returns healthy
curl -s https://aforden.aformix.com/api/health
```

> [!WARNING]
> **Operational Gap Notice**: Performing manual migrations prior to Vercel deployment introduces human error risk. When a CI/CD platform (e.g. GitHub Actions) is adopted in future phases, this step should be automated as a protected deploy pipeline gate before traffic migration.

## 5. Connection Health Monitoring

Aforden implements two complementary database health checks:

1. **Public Infrastructure Probe (`GET /api/health`)** ([`app/api/health/route.ts`](file:///d:/Download/aforden/app/api/health/route.ts)):
   - Unauthenticated liveness probe for Vercel, load balancers, and external status monitors.
   - Executes `SELECT 1` via `prisma.$queryRaw`.
   - **Response on Success**: HTTP 200 `{ "status": "healthy", "timestamp": "..." }`.
   - **Response on DB Unreachable**: HTTP 503 `{ "status": "unhealthy", "error": "Service unavailable: database connectivity check failed" }`.
   - Strict `cache-control: no-store` prevents stale health status caching.
2. **Platform Operational Diagnostics (`GET /api/platform/health`)** ([`lib/services/platform/health/platformHealthService.ts`](file:///d:/Download/aforden/lib/services/platform/health/platformHealthService.ts)):
   - Authenticated operator probe gated by `platform.operations.view_queues`.
   - Measures live DB round-trip ping latency (flags `DEGRADED` if >250ms).
   - Reports connection pool responsiveness state.

## 7. Destructive-Operation Protection & Multi-Tenancy Boundary

### 7.1 Runtime DDL Audit
Automated source code scanning of all `.ts` and `.tsx` files in `app/` and `lib/` verified:
- **Zero runtime DDL statements** (`ALTER TABLE`, `DROP TABLE`, `TRUNCATE TABLE`, `DROP DATABASE`).
- The only `$executeRaw` calls in the application are transaction savepoint controls (`SAVEPOINT`, `RELEASE SAVEPOINT`, `ROLLBACK TO SAVEPOINT`) in [`lib/services/inventory/balance/lockInventoryBalance.ts`](file:///d:/Download/aforden/lib/services/inventory/balance/lockInventoryBalance.ts).
