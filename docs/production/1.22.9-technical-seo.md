## 1. Executive Summary

Phase 1.22.9 establishes the production **Technical SEO foundation** for the Aforden platform on its canonical origin `https://aforden.aformix.com` (formalized in Phase 1.22.8).

While public marketing and product content pages are scheduled for **Phase 1.25**, this phase guarantees that the entire technical scaffolding—App Router metadata conventions, dynamic crawler directives (`robots.txt`), automated XML sitemaps (`sitemap.xml`), Schema.org structured data injection, and multi-tier indexation defense-in-depth—is fully operational, verified, and strictly isolated from private application planes.

### Core Architectural Guarantees
1. **Dynamic Domain Resolution**: All canonical links, Open Graph tags, sitemaps, and robots directives resolve dynamically against `NEXT_PUBLIC_APP_URL` with a fallback to `https://aforden.aformix.com`. Zero hardcoded environment URLs exist in crawler contracts.
2. **Strict Multi-Plane Boundary Protection**: The dynamic `robots.txt` and request proxy enforce strict indexation barriers between public surfaces (`/`) and internal planes (`/api/*`, `/dashboard/*`, `/work-orders/*`, `/invoices/*`, `/quotes/*`, `/inventory/*`, `/schedules/*`, `/customers/*`, `/settings/*`, `/workspaces/*`, `/platform/*`, `/technician/*`, and authentication endpoints).
3. **Defense-in-Depth Indexation (`X-Robots-Tag`)**: Edge proxy middleware injects `X-Robots-Tag` HTTP headers at the transport layer, guaranteeing that Vercel preview deployments (`*.vercel.app`) are never indexed (`noindex, nofollow, noarchive`), internal operational APIs are barred (`noindex, nofollow`), and authentication forms pass link equity without indexing (`noindex, follow`).
4. **Real-Data Structured Data**: Schema.org JSON-LD helpers for `Organization` and `WebSite` use authentic entity attributes only, avoiding hallucinated addresses, dates, or contact channels.
5. **Phase Hygiene**: No marketing content pages were generated (deferred to Phase 1.25), and no AEO/`llms.txt` artifacts were introduced (deferred to Phase 1.22.10).

## 2. Next.js App Router Metadata Convention (`app/layout.tsx`)

Aforden adopts the modern Next.js 15+ App Router metadata convention using exported static `Metadata` on `app/layout.tsx`. Downstream sub-pages inherit and customize this structure using the title template.

### 2.1 Configuration Details
- **Base Resolution (`metadataBase`)**: Configured with `new URL(rawAppUrl)`. All relative canonical URLs and Open Graph assets automatically resolve against the canonical domain.
- **Title Template**:
  - `template: "%s | Aforden"`
  - `default: "Aforden | Modern Field Service & Workforce Management"`
- **Meta Description**: `"Next-generation multi-tenant field service management platform for HVAC, electrical, plumbing, and specialty trade enterprises."`
- **Canonical Alternate**: Relative canonical link `./` resolves against `metadataBase` to produce `https://aforden.aformix.com/` on the root, preventing duplicate content penalties across preview domains or query string variations.
- **Open Graph Protocol**:
  - `type: "website"`
  - `siteName: "Aforden"`
  - `locale: "en_US"`
  - `images: [{ url: "/og-image.png", width: 1200, height: 630, alt: "Aforden Platform" }]`
- **X / Twitter Cards**:
  - `card: "summary_large_image"`
  - `title: "Aforden | Modern Field Service & Workforce Management"`
  - `creator: "@aforden"`
- **Robots Default**:
  - `index: true`, `follow: true` (for allowed public pages).
  - Explicit Googlebot controls: `index: true`, `follow: true`, `'max-video-preview': -1`, `'max-image-preview': 'large'`, `'max-snippet': -1`.
- **Icons & Manifest**: Standard `/favicon.ico` and `/site.webmanifest` linkage.

## 3. Dynamic `robots.txt` Architecture (`app/robots.ts`)

Instead of a static file, Aforden utilizes Next.js dynamic route handler convention `app/robots.ts` returning `MetadataRoute.Robots`.

### 3.1 Policy Directives
- **Allowed Routes**: `/` (and future public marketing pages under Phase 1.25).
- **Disallowed Routes**:
  - Internal REST API: `/api/`
  - Multi-Tenant Operational Planes: `/dashboard/`, `/work-orders/`, `/invoices/`, `/quotes/`, `/inventory/`, `/schedules/`, `/customers/`, `/settings/`, `/workspaces/`

  - Technician Mobile Web App: `/technician/`
  - Public Auth Entrypoints: `/login`, `/register`, `/forgot-password`, `/reset-password`, `/verify-email`

## 4. Dynamic `sitemap.xml` Architecture (`app/sitemap.ts`)

Aforden generates its XML sitemap dynamically using Next.js `app/sitemap.ts` returning `MetadataRoute.Sitemap`.

### 4.1 Specification
- **Indexed URLs**: Currently strictly `/` (the root public landing page).
- **Change Frequency**: `weekly`.
- **Priority**: `1.0`.
- **Timestamp**: Synchronized to deployment / build timestamp (`lastModified: new Date()`).
- **Phase 1.25 Extension**: Structured as an array of route definitions so Phase 1.25 pages (`/features`, `/pricing`, `/about`, `/contact`, `/docs`, `/blog`) can be added directly without restructuring.

### 4.2 Rendered `sitemap.xml` Output
When requested at `https://aforden.aformix.com/sitemap.xml`, the endpoint produces:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://aforden.aformix.com</loc>

    <changefreq>weekly</changefreq>
    <priority>1.0</priority>
  </url>
```

## 5. Structured Data Foundation (`lib/seo/` & `components/seo/`)

To provide search engines with machine-readable metadata conforming to Schema.org standards, Aforden introduces a typed structured data module and an XSS-sanitized React component.

### 5.1 Architecture
- **Schema Factory (`lib/seo/structuredData.ts`)**:
  - `buildOrganizationSchema(baseUrl)`: Generates `@type: "Organization"` with authentic platform identifiers:
    - `@context`: `"https://schema.org"`
    - `name`: `"Aforden"`
    - `legalName`: `"Aforden"`
    - `url`: `https://aforden.aformix.com`
    - `logo`: `https://aforden.aformix.com/logo.png`
    - `description`: Platform description.
  - `buildWebSiteSchema(baseUrl)`: Generates `@type: "WebSite"`:
    - `@context`: `"https://schema.org"`
    - `name`: `"Aforden"`
    - `url`: `https://aforden.aformix.com`
- **Sanitized Component (`components/seo/JsonLd.tsx`)**:
  - Server Component injecting `<script type="application/ld+json">`.
  - Escapes `<` to `\u003c` via `JSON.stringify(schema).replace(/</g, "\\u003c")` to prevent JSON-in-script XSS vulnerabilities.
- **Root Page Injection (`app/page.tsx`)**:
  - Root landing page embeds both schemas.

### 5.2 Real Data Guarantee
In strict compliance with project guidelines, **no fake addresses, telephone numbers, founding dates, or fictitious team members** were added. The schemas reflect only verified platform entity identity.

## 6. Indexation Controls & Defense-in-Depth (`X-Robots-Tag`)

Crawl policies must not rely solely on `robots.txt` (which well-behaved bots obey, but search engines can still index URLs from external links without crawling page contents). Aforden implements HTTP header defense-in-depth inside `lib/api/securityHeaders.ts` and `proxy.ts`.

### 6.1 Defense-in-Depth Tiers

| Traffic Tier | Matching Condition | `X-Robots-Tag` Header Value | Purpose |
| :--- | :--- | :--- | :--- |
| **Vercel Preview Deployments** | `VERCEL_ENV === "preview"` OR Host ends with `.vercel.app` | `noindex, nofollow, noarchive` | Complete elimination of preview/branch build indexing across all search engines |
| **Internal Application Planes & APIs** | Path starts with `/api/`, `/dashboard`, `/work-orders`, `/invoices`, `/quotes`, `/inventory`, `/schedules`, `/customers`, `/settings`, `/workspaces`, `/platform`, `/technician` | `noindex, nofollow` | Transport-level barrier preventing deep-link indexing of private tenant views |
| **Public Auth Entrypoints** | Path is `/login`, `/register`, `/forgot-password`, `/reset-password`, `/verify-email` | `noindex, follow` | Prevents indexation of login forms while permitting search crawlers to follow outbound links |
| **Public Production Marketing Surface** | Root `/` (and future Phase 1.25 public marketing paths) on canonical production host | `null` (Header omitted) | Indexation governed normally by `app/robots.ts` and page `<meta name="robots">` |

### 6.2 Transport Pipeline Integration
`proxy.ts` executes `applyIndexationHeaders(response.headers, pathname, host)` on all response flows:
1. Public API versioning preflight and error responses (`/api/v...`).
2. Global REST API security responses (`/api/...`).
3. Normal downstream responses via `NextResponse.next()`.
