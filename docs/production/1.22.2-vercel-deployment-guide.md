## 2. Preview Deployments Configuration & Environment Scoping

### 2.1 Preview Deployment Lifecycle
- **Branch/PR Triggers**: Every `git push` to a non-production branch or any Pull Request opened against `main` automatically provisions a Preview Deployment.
- **Preview URLs**: Vercel allocates a unique, HTTPS-enabled domain for every preview (e.g., `aforden-git-<branch>-<team>.vercel.app`).
- **PR Feedback Integration**: The Vercel GitHub Bot automatically posts a sticky comment on the Pull Request containing preview URLs, deployment statuses, and build inspection links.
- **Edge & Serverless Isolation**: Preview deployments run in an isolated serverless plane. However, to prevent preview test traffic from polluting or corrupting production data, environment variables must be strictly scoped.

### 2.2 Environment Variable Scoping Matrix

## 3. Production Deployment & Runtime Configuration

### 3.1 Node.js Engine Pinning
- **Specification**: In Phase 1.22.1, the Node.js runtime was explicitly pinned:
  - [`.nvmrc`](file:///d:/Download/aforden/.nvmrc): `20.18.0`
  - [`package.json:13-16`](file:///d:/Download/aforden/package.json#L13-L16):
    ```json
    "engines": {
      "node": ">=20.18.0 <23.0.0",
      "npm": ">=10.0.0"
    }
    ```
- **Vercel Engine Selection**: Vercel inspects `.nvmrc` and the `engines.node` range in `package.json` during the build environment initialization. With `20.18.0` pinned, Vercel automatically selects the **Node.js 20.x LTS** serverless runtime.

### 3.2 Build Command & Vercel Build Environment
- **Build Command**: `next build`
- **Recommended Vercel Environment Variables**:
  - `NEXT_TELEMETRY_DISABLED=1`: Disables anonymous Next.js telemetry reporting during production builds.
  - `CI=1`: Standard Continuous Integration flag ensuring strict error exit codes.

## 4. Vercel Cron Scheduling & Invocations

Scheduled background routines are defined in [`vercel.json`](file:///d:/Download/aforden/vercel.json) and dispatched via HTTP GET with bearer authentication:

| Cron Path | Schedule | Cadence | Underneath Service Handlers |
| :--- | :--- | :--- | :--- |
| `/api/cron/billing-reconciliation` | `0 * * * *` | Hourly (at minute 0) | `runReconciliationSweep(prisma)` |
| `/api/cron/notification-reconciliation` | `*/15 * * * *` | Every 15 minutes | `reconcileStuckDeliveries(prisma)`, `reconcileStuckOutboxItems(prisma)` |
| `/api/cron/session-cleanup` | `0 0 * * *` | Daily (at 00:00 UTC) | `cleanupExpiredSessions()` |

All cron endpoints require `Authorization: Bearer ${CRON_SECRET}`. Requests missing or presenting mismatched secrets are immediately rejected with HTTP 401.
