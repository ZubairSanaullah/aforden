## 2. Scope 1: DNS Record Architecture & Delegation Safety

### 2.1 Exact DNS Record Specification
To delegate the subdomain `aforden.aformix.com` to Vercel while keeping the parent domain `aformix.com` under its existing DNS provider, configure the following single DNS record in the DNS management console for `aformix.com`:

| Field | Configuration Value | Operator Notes |
| :--- | :--- | :--- |
| **Record Type** | `CNAME` | Standard canonical name alias record |
| **Host / Name** | `aforden` | In some DNS panels (e.g. Cloudflare, Route 53), enter `aforden`. In panels requiring FQDN, enter `aforden.aformix.com.` |
| **Value / Target** | `cname.vercel-dns.com` | Vercel's global edge Anycast DNS target (append trailing dot `cname.vercel-dns.com.` if required by provider) |
| **TTL** | `Auto` or `300` (5 min) / `60` (1 min) | Low TTL recommended during initial rollout for rapid verification |
| **Proxy Status** | **DNS Only** (Grey Cloud if Cloudflare) | Crucial if parent domain uses Cloudflare (see §2.3) |

### 2.2 Subdomain Delegation & Zone Isolation Safety
Configuring a `CNAME` record specifically for the host `aforden` operates with complete cryptographic and routing isolation under standard DNS specifications (RFC 1034 / RFC 2181):

- **Apex Domain (`aformix.com`)**: Completely untouched. Any existing `A`, `AAAA`, or `ALIAS` records pointing to the main Aformix corporate website continue to resolve without interference.
- **`www.aformix.com`**: Completely untouched.
- **Mail Exchanger (`MX`) Records**: Completely untouched. Email routing for `@aformix.com` (e.g. Google Workspace, Microsoft 365, Proton, etc.) remains fully operational because MX records bind to `@` (apex) and are never affected by child subdomain records.
- **Email Security & Authenticity (`TXT` Records)**: Completely untouched. Root `SPF`, `DKIM` (`*._domainkey.aformix.com`), and `DMARC` (`_dmarc.aformix.com`) policies remain completely intact.
- **Sibling Subdomains**: Any existing subdomains (e.g. `api.aformix.com`, `mail.aformix.com`, `staging.aformix.com`) remain completely independent.

## 3. Scope 2: Vercel Project Custom Domain Configuration

The Vercel dashboard configuration binds `aforden.aformix.com` to the production deployment environment.

*(To be executed manually by Zubair in the Vercel Dashboard)*

1. Log into the Vercel Dashboard at [https://vercel.com](https://vercel.com).
2. Select the **`aforden`** project.
3. Click on the **Settings** tab in the top navigation bar.
4. Click **Domains** in the left sidebar menu.

   ```text

   ```
6. Click **Add**.
7. In the configuration dialog, verify the environment mapping:
   - **Environment**: **Production** (attached to the canonical `main` branch).
   - **Redirect**: *No redirect* (this is the primary canonical production origin).
8. Vercel will immediately inspect global DNS for the `CNAME` record pointing to `cname.vercel-dns.com`.

### 3.2 Environment Isolation: Production vs Preview Deployments
- **Production Environment**: The custom domain `aforden.aformix.com` binds **strictly and exclusively** to deployments generated from the production branch (`main`).
- **Preview Deployments**: Every pull request, feature branch, and review build automatically provisions an isolated, unique preview URL under the Vercel wildcard namespace (e.g. `aforden-git-<branch>-<team>.vercel.app`).
- **Isolation Guarantee**: Preview builds never receive traffic from `aforden.aformix.com`, preventing preview testing from contaminating production analytics, Auth.js sessions, or customer traffic.

## 4. Scope 3: Automated SSL/TLS (Let's Encrypt)

### 4.1 Automated Certificate Issuance & Renewal
Vercel provides native, automated SSL/TLS certificate management through **Let's Encrypt**:
- **Zero Manual Key/CSR Generation**: Operators do not need to generate Certificate Signing Requests (CSRs), private keys, or buy third-party SSL certificates.
- **Automated ACME Validation**: As soon as the `CNAME` record points to `cname.vercel-dns.com`, Vercel's edge infrastructure automatically completes the Let's Encrypt ACME HTTP-01 / TLS-ALPN-01 challenge.
- **Automated Renewal**: Certificates are renewed automatically every 60 days with zero operator downtime or manual intervention.
- **Modern Cipher Suites & TLS 1.3**: Certificates support TLS 1.2 and TLS 1.3 with forward secrecy (ECDHE-RSA-AES128-GCM-SHA256, ECDHE-ECDSA-AES128-GCM-SHA256).

### 4.2 Expected Verification & Propagation Timeline
To prevent operators from misdiagnosing normal DNS propagation as an infrastructure failure, the expected turnaround timeline is:

| Stage | Expected Duration | Notes |
| :--- | :--- | :--- |
| **DNS Record Propagation** | **2 to 15 minutes** | Depends on the TTL of the authoritative DNS nameservers for `aformix.com`. In rare global propagation anomalies, can take up to 24–48 hours. |
| **Vercel DNS Polling** | **1 to 3 minutes** | Vercel checks DNS at regular intervals. Clicking **Refresh** in the Vercel Domains dashboard forces an immediate check. |
| **Let's Encrypt Certificate Issuance** | **1 to 5 minutes** | Handled automatically once Vercel confirms DNS resolution. |
| **Global Edge Activation** | **< 60 seconds** | Edge nodes worldwide sync the SSL certificate and start terminating HTTPS. |
| **Total Expected Time** | **5 to 30 minutes** | Normal operational window from DNS creation to active HTTPS site. |

### 5.2 `AUTH_TRUST_HOST` Behavior in Auth.js v5 on Vercel
In Auth.js v5 (NextAuth v5 beta), when running behind Vercel's edge reverse proxy:
- Requests arrive at the serverless Next.js function with forwarded headers (`x-forwarded-host: aforden.aformix.com`, `x-forwarded-proto: https`).
- Declaring `AUTH_TRUST_HOST="true"` explicitly instructs Auth.js to trust the forwarded headers and resolve redirect URLs and callback verification endpoints against `https://aforden.aformix.com` without throwing `UntrustedHost` errors.
- In Vercel Project Settings (**Settings** $\rightarrow$ **Environment Variables**), `AUTH_TRUST_HOST="true"` must be set for **Production** and **Preview** environments.

### 5.3 Host-Only Cookie Scoping Re-Confirmation (RFC 6265)
The cookie configuration in [`auth.ts`](file:///d:/Download/aforden/auth.ts) was audited in Phase 1.22.5 and re-verified here:

```typescript
// auth.ts lines 20-57
sessionToken: {
    name: process.env.NODE_ENV === "production" ? "__Secure-authjs.session-token" : "authjs.session-token",
    options: {
        httpOnly: true,
        sameSite: "lax",
        path: "/",
        secure: process.env.NODE_ENV === "production",
        // Crucial: domain attribute is deliberately OMITTED
    },
},
csrfToken: {
    name: process.env.NODE_ENV === "production" ? "__Host-authjs.csrf-token" : "authjs.csrf-token",
    options: {
        httpOnly: true,
        sameSite: "lax",
        path: "/",
        secure: process.env.NODE_ENV === "production",
        // Crucial: domain attribute is deliberately OMITTED
    },
}
```

**Security Analysis**:
1. **RFC 6265 Host-Only Invariant**: When the `Domain` attribute is omitted from a `Set-Cookie` header, the browser marks the cookie as **Host-Only**. It will be transmitted **only** to the exact origin `aforden.aformix.com` and will **never** be sent to parent domains (`aformix.com`) or sibling subdomains (`api.aformix.com`, `corp.aformix.com`).
2. **`__Host-` Prefix Compliance**: Under the W3C Cookie Prefixes specification, cookies prefixed with `__Host-` (such as `__Host-authjs.csrf-token`) are strictly rejected by modern browsers if they declare a `Domain` attribute. Omitting `domain` is a cryptographic and browser-level requirement for CSRF defense.
3. **Cross-Tenant Attack Surface Elimination**: If `domain: "aformix.com"` were erroneously configured, any other service or compromised endpoint under `*.aformix.com` could inspect or overwrite Aforden session tokens. Host-only scoping provides 100% origin isolation.

## 6. Scope 5: Public vs Private Route Boundary (Architecture Decision)

Ahead of Phase 1.22.9 (SEO & Search Engine Crawlability) and Phase 1.25 (Public Marketing Site), the product domain topology is formally locked:

### 6.1 Architectural Decision: Unified Subdomain Model (`aforden.aformix.com`)

| Evaluated Architecture | Description | Decision | Rationale |
| :--- | :--- | :---: | :--- |
| **Model A (Unified Subdomain)** | `aforden.aformix.com` serves **both** the public marketing site and the authenticated web application. | **APPROVED** | 1. Avoids creating a 4th-level nested subdomain (`app.aforden.aformix.com`).<br>2. Keeps DNS, SSL, and Vercel routing under a single configuration.<br>3. Eliminates cross-origin CORS and cross-subdomain cookie issues.<br>4. Search engine indexing is cleanly scoped via `robots.txt` and `sitemap.xml`. |
| **Model B (Split Subdomain)** | `aforden.aformix.com` is marketing only; `app.aforden.aformix.com` is the application. | *Rejected* | Requires two DNS CNAME records, two Vercel domain attachments, complex cross-subdomain authentication redirect handling, and introduces unnecessary operational complexity. |

### 6.2 Route Classification Contract for Phase 1.22.9

Under the Unified Subdomain Model, routes on `https://aforden.aformix.com` fall into four distinct categories:

```
                            https://aforden.aformix.com
                                         |
     +-------------------+---------------+-------------------+-------------------+
     |                   |                                   |                   |
     v                   v                                   v                   v
[ Public Marketing ] [ Public Auth ]                   [ Authenticated App ] [ System Endpoints ]
  - /                 - /login                          - /dashboard/*        - /api/cron/*
  - /features         - /register                       - /work-orders/*      - /api/health
  - /pricing          - /forgot-password                - /invoices/*         - /api/v1/*
  - /terms            - /reset-password                 - /inventory/*        - /api/platform/*
  - /privacy                                            - /settings/*
  (Indexable)         (noindex, follow)                 (Disallow in robots)  (Disallow in robots)
```

1. **Public Marketing Pages (Indexable & in `sitemap.xml`)**:
   - `/` (Landing Page)
   - `/features` (Product Capabilities)
   - `/pricing` (Subscription Tiers)
   - `/terms` (Terms of Service)
   - `/privacy` (Privacy Policy)
   - `/contact` (Contact / Support Inquiry)
2. **Public Authentication Flows (Accessible, but `noindex, follow`)**:
   - `/login`, `/register`, `/forgot-password`, `/reset-password`, `/verify-email`
   - Excluded from `sitemap.xml`; tagged with `<meta name="robots" content="noindex, follow" />`.
3. **Authenticated Application Planes (Blocked in `robots.txt`)**:
   - `/dashboard`, `/work-orders`, `/invoices`, `/quotes`, `/schedules`, `/customers`, `/inventory`, `/settings`, `/platform`
   - Explicitly disallowed in `robots.txt` (`Disallow: /dashboard/`, `Disallow: /workspaces/`, etc.).
4. **Backend API & Cron Pipelines (Blocked in `robots.txt`)**:
   - `/api/*` (disallowed from search engine crawlers).

## 7. Scope 6: Redirects & Transport Security

### 7.1 Non-www Canonicalization
Because `aforden.aformix.com` is already a 3rd-level subdomain under `aformix.com`:
- The canonical domain is strictly **non-www**: `https://aforden.aformix.com`.
- `www.aforden.aformix.com` (a 4th-level subdomain) is not used, avoiding DNS clutter and SSL SAN certificate complications.

### 7.2 Automatic HTTP $\rightarrow$ HTTPS Redirection
Transport security is enforced at two distinct layers:
1. **Vercel Edge Redirection**: Vercel's global edge network automatically intercepts any plain HTTP request (`http://aforden.aformix.com/...`) and responds with an **HTTP 308 Permanent Redirect** to `https://aforden.aformix.com/...`.
2. **HSTS Header Enforcement**: Confirmed in Phase 1.22.7, [`proxy.ts`](file:///d:/Download/aforden/proxy.ts) attaches `Strict-Transport-Security: max-age=31536000; includeSubDomains` on every response. Once a browser visits the domain over HTTPS, it will automatically rewrite all subsequent insecure HTTP requests to HTTPS client-side for 1 full year without generating network traffic.
